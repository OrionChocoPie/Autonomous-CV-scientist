# Hackathon submission guide

## Problem statement

**Push the Frontier:** accelerate the experimental loop for computer vision.
CV Scientist helps engineers decide which intervention to test, understand why
it failed, and retain evidence instead of repeating unsupported ideas. The
industrial-inspection example makes that workflow reproducible without private data.

The model's job is to investigate and propose. Matching, metrics, frozen-input
checks and acceptance decisions are performed by application code. This is an
experiment-analysis system with persistent evidence and a bounded evaluator,
not a single-image description endpoint.

## Verified judging rubric

The official [Application Overview and Event Waiver](https://cerebralvalley.ai/e/meta-ai-developer-hackathon/waiver)
specifies the following project judging weights. They are distinct from the
equally weighted criteria for participant applications on the event landing page.
The supplied participant guide describes scoring each criterion from 0 to 10.

| Criterion | Weight | Evidence in this repository |
|---|---:|---|
| Impact | 30% | A concrete CV-engineer workflow; lost small-defect recall visible despite aggregate improvement; retained negative results in the [case study](case-study.md) |
| Use of Meta AI Tooling | 25% | Muse Wonder / Spark tool calling, selected-image input, structured proposals, field mapping and evidence validation; [integration map](meta-integration.md) |
| Technical Depth & Execution | 20% | Class-aware matching, transactional ingestion, immutable import revisions, frozen evaluation inputs, resource budgets, journals, recovery and [automated tests](../tests/) |
| Demo | 25% | [Public synthetic workspace](../examples/create_demo.py), HTML error overlays, optional live Muse investigation and a [three-minute recording script](demo.md) |

These links show where to assess the work; they do not assert a score or guarantee
acceptance. The organizers make the eligibility and judging decisions.

## Original work

Read [contributions.md](contributions.md) before recording. The demo must identify
the earlier workspace foundation separately from the features built during the
hackathon. The contributor confirmed that the additional feature work captured in this submission
was developed during the event. The contribution map records that scope without
claiming the entire foundation as new.

## Submission requirements

| Requirement from participant guide | Repository support / remaining action |
|---|---|
| Public open-source repository | MIT [LICENSE](../LICENSE), documented install and CI are included. Create a public GitHub repository and verify anonymous access. |
| Meaningful Meta model integration | Real Meta HTTP client and multimodal tool loop are implemented. A live demo requires your Meta account and key. |
| Clearly identified original contributions | [Contribution map](contributions.md) and opening line in the recording script. |
| Working product and three-minute demo video | Offline product demo is reproducible. Record and publish the video; no video link is claimed here. |
| Maximum four participants, all contributors listed | Complete the team and representative fields in the submission form; repository authorship does not fill those fields. |
| Rights to code, data and assets | Application code is MIT; public demo assets are generated by this repository. Private case-study images, labels and weights are not distributed. Third-party services and packages retain their own terms. |
| Submission through Cerebral Valley | Submit the public repository and video at the [submission portal](https://cerebralvalley.ai/e/meta-ai-developer-hackathon/hackathon/submit). A Git commit is not a submission. |

## Before submitting

- [ ] Public repository opens in a signed-out browser.
- [ ] Install and demo commands work from the public checkout; hosted CI passes.
- [ ] The three-minute video link opens without requesting access.
- [ ] The video identifies new work and demonstrates a real Meta call without exposing keys.
- [ ] Everyone who contributed is listed, with one representative and one chosen track.
- [ ] Check current organizer instructions and submit the completed form.

Local preparation cannot verify these external steps. See
[publishing instructions](publishing.md) for the GitHub handoff.
